# UI 设计稿与实际页面视觉走查

## 使用方式

向子级代理同时提供同尺寸、同视口的两张截图：设计稿（左）与实际页面（右）。将下列提示词原样发送，并附上页面路径、目标断点及截图。

## 可直接使用的提示词

```text
请作为资深 UI 走查专家，对比图中的设计稿（左）与实际页面（右）。

先确认两张图的视口尺寸、缩放比例和页面状态一致；若不一致，明确说明无法做像素级比较的原因。随后以页面区块和组件为单位逐一检查，不要只给笼统结论。

请严格从以下维度指出视觉偏差，并给出可执行的修改建议：

1. 组件对齐：页面边界、栅格、标题、按钮、表单控件、表格、卡片、图例、图表轴的水平与垂直对齐。
2. 字体：字体大小、行高、字重、字色，以及标题、正文、辅助文本、数值之间的层级差异。
3. 间距：容器 Padding、组件 Margin、卡片间距、标题与内容间距、控件间距、表格行列间距。
4. 色彩：背景、边框、阴影、主色、状态色、文字色。尽可能给出设计稿与实际页面的 Hex Code；无法可靠取色时标记为“需取色确认”，不得猜测。
5. 尺寸与样式：圆角、边框宽度、阴影、按钮高度、图标尺寸、控件宽高、响应式换行与溢出。

输出为按优先级排序的 Markdown 表格，列为：

| 优先级 | 区块/组件 | 视觉维度 | 设计稿表现 | 实际页面表现 | 偏差 | 修改建议 |

要求：

- 优先级仅使用 P0（明显破坏布局/可用性）、P1（显著视觉不一致）、P2（细节优化）。
- 每条建议必须定位到可修改的 CSS/组件属性，例如“将 `.holiday-analysis__metric-grid` 的 gap 从 16px 调整为 12px”。
- 对字体、间距、颜色、尺寸给出明确数值；仅在截图信息不足时说明验证方式。
- 最后给出“修复顺序建议”和“需产品/设计确认项”。
- 不修改代码；本次任务只输出走查报告。
```
